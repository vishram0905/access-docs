    Test report¶

    Work in progress

    The ACCESS app is a working prototype under active development. This report records the state of the demonstration build tested on 12 October 2026. Figures will change as the verified library grows.

    Run: 12 October 2026, 06:26 SGT · Suite: 49 automated tests in 12 areas Library under test: 373 claim-verified programmes · Status of the app: work in progress (demo build)

    1. Summary¶
    Tests run 49, in 12 areas
    Passed 48
    Failed 1 (D2: three of fourteen test profiles receive fewer than five results; a coverage gap, not a logic error)
    Defects found and fixed while preparing and running the suite 10 in the app, 3 in the test suite itself (Section 5)
    Wall-clock time 31 s with warm caches; about 2 min when the AI services are called afresh

    The core promise of the app holds in every test: every programme shown matches the researcher's chosen country, funding type and career stage, every displayed eligibility rule is quoted from the funder's official page, and the same input always gives the same answer. The remaining weakness is coverage: some combinations (for example a master's degree in Japan, or mid-career research grants) return only one to four programmes because few verified programmes exist for them yet.

    2. Scope and method¶

    The suite tests the app as a user meets it (the four pages and the search form) and the components behind it (eligibility gate, search library, retrieval, AI ranking, question answering, application plans). Three kinds of test are used:

    • Example-based tests compare an output with a known correct answer (for example, 37 hand-checked eligibility cases).
    • Property and integrity tests check a statement that must hold for every item (for example, "every rule's quote appears on the official page", checked for all 633 rules).
    • Metamorphic tests compare related searches when the correct answer for one search is unknown. If a researcher adds a country, no result for the countries already chosen may disappear. Such relations expose logic errors without a labelled ground truth.

    Fourteen realistic researcher profiles are used across the suite: the four example researchers on the home page and ten new ones that vary nationality, career stage, field, destination and funding type (Appendix A).

    The AI tests (H to J) use the free-tier models deployed in the app. Their outputs are cached, so repeated runs are fast and reproducible, and latencies reported for them come from the first, uncached run.

    C. Retrieval quality¶

    Known-item benchmark: for each programme, an independent model wrote the query a qualifying researcher would type, without the programme's or funder's name. The test uses the 54 benchmark programmes that are in today's verified library and searches the whole library with the hybrid method used by the app.

    Measure Result
    Recall@1 0.74
    Recall@5 0.93
    Recall@10 0.96
    Mean reciprocal rank 0.82

    These figures match the earlier benchmark on the larger, partly unverified library (recall@5 0.93), so restricting search to verified programmes did not reduce retrieval quality.

    4. Known limitations¶

    1. Coverage (D2): a few combinations return one to four programmes. The library holds 373 verified programmes and grows as the critic verifies the backlog.
    2. Unresolved host countries (B10): 32 verified programmes list several host countries that are not yet resolved. They are excluded from country searches, so a researcher choosing a country may miss some of them. Resolution needs the Gemini extractor, whose free quota resets daily at about 15:00 SGT.
    3. Near misses are rare: the gate finds near misses correctly (unit tests), but funder pages seldom state numeric thresholds, so most profiles see none.
    4. Q&A depends on the stored page (I1): short or third-party pages often lead to "the official page does not say".
    5. Data errors the checks cannot catch: an eligibility rule that the extractor missed cannot be enforced. The independent reviewers flag some of these as "weaker fit" (for example, a postdoc programme restricted to US and Canadian scholars), but the programme is still listed as eligible.
    6. Free-tier dependence: AI ranking takes about 10 s to 2 min depending on quota. Results always appear first and remain usable if the AI services are unavailable.

    5. Defects found and fixed¶

    In the app¶

    # Defect How it was found Fix Evidence after the fix
    D-1 An edited example search ("Wei Ling" changed to a master's student in cancer research) replaced the real example, so the form and the results did not match Manual check of the examples in the browser A saved search counts as an example only if its form is unedited; examples regenerated K2, L5
    D-2 187 programmes that had not passed the claim check were searchable Consistency harness (97 unverified results across profiles) Search library holds verified programmes only B1
    D-3 With fewer than 8 matches, the country filter was silently dropped and programmes from other countries appeared Consistency harness (9 wrong-country results for one profile) A filter is relaxed only when nothing matches, and the page says so D1, F12
    D-4 Programmes labelled "Multiple" matched every country search Consistency harness Excluded from country searches until resolved D1, B10
    D-5 A PhD candidate was told a grant requiring at least 7 years since the PhD would be "met once your PhD is awarded" Consistency harness (stage check) Such rules now fail for PhD candidates A1 (2 new cases)
    D-6 A working professional with a master's degree was excluded from every PhD scholarship Robustness test F9 Holding the preceding degree qualifies as an applicant F9, A1 (3 new cases)
    D-7 One-off calls that had closed, and calls named for a past year ("2020-21"), were shown as current Consistency harness Dropped or marked closed and listed last D1
    D-8 Match scores were not in order on screen (for example 82, 77, 71, then 89) Manual check in the browser Strong matches by score, then weaker fits by score under a heading H1 to H3
    D-9 The local reviewer model was benched after timeouts caused by the background critic, so live searches reported reviewer errors Trace of test H On demo days the local model serves live searches only H1 to H3 (no reviewer errors)
    D-10 Generic or identical titles ("Research Fellowships", two "ASEAN Undergraduate Scholarship") were ambiguous Consistency harness The funder is added to such titles Section 3D

    In the test suite¶

    Errors in the tests themselves were found by their first results and corrected, so that a pass means what it says: E6 originally could not fail, F12 expected the wrong behaviour (a country with no programmes correctly shows programmes open to any country), and the interface tests first loaded pages outside the app's navigation.

    6. How to reproduce¶

    The suite is a single script in the project's code repository, which is kept private while the prototype is under development. It runs all 49 tests in about two minutes (under 30 seconds without the AI tests) and writes every result, with its measurements, to one results file.
